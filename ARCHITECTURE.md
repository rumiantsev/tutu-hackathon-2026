# Архитектура

Bleisure-калькулятор — это встраиваемый B2B-виджет с «тупым» фронтом и тонким
бэкендом, который оборачивает поиск **MCP Tutu** (`https://mcp.tutu.ru/mcp`) и
возвращает виджету готовый к рендеру payload. Оплата на стороне Tutu; сервис
только читает поиск и строит checkout-ссылки.

## Обзор

```
┌───────────────┐   HTTP (fetch)    ┌──────────────────────────┐
│  demo.html +   │ ─────────────────▶│  /api/bleisure            │
│  widget.js     │  JSON payload     │  /api/bleisure-quiz       │
│  (dumb front)  │ ◀─────────────────│  (serverless Vercel)      │
└───────────────┘                   └────────────┬─────────────┘
                                                 │ JSON-RPC over HTTP
                                                 ▼
                                       ┌──────────────────────┐
                                       │  MCP Tutu (search)   │
                                       │  read-only + deeplink│
                                       └──────────────────────┘
```

Два входа в один расчёт:

- `server.js` — локальный dev-сервер (статика + `/api/bleisure`), для разработки.
- `api/bleisure.js` и `api/bleisure-quiz.js` — serverless-функции Vercel.

Оба импортируют общий вычислительный модуль `bleisure.js`, поэтому логика расчёта
живёт в одном месте и не дублируется между dev и prod.

## Слои и ответственность

### 1. Фронт — «тупой» виджет (`widget.js` + `widget.css` + `demo.html`)

- Без зависимостей и сборки: обычный `<script>` + `<link>`.
- Два способа встраивания: через `data-bleisure-widget` атрибут (готовый payload)
  или `data-bleisure-src` (подгрузка JSON с бэкенда).
- Не знает про MCP, даты, логику сплита — только рендерит полученную схему
  (`trip`, `transport`, `hotel`, `split`, `disclaimer`).
- Весь пользовательский ввод экранируется (`esc`), стили — под префиксом `.bls-`.

### 2. Вычислительный модуль (`bleisure.js`)

Чистая функция `computeBleisure(query) → payload`:

1. Определяет сторону продления: выезд в понедельник → `extendSide="departure"`
   (приезд в субботу), иначе `"return"` (возврат в воскресенье).
2. Для меняющейся ноги зовёт `search_multitransport`, затем по каждому доступному
   типу — `search_rail` / `search_bus` / `search_avia` (по одному офферу).
3. `search_hotels` на даты выходных; рекомендация — самый дешёвый с завтраком и
   бесплатной отменой (фолбэк по приоритетам), альтернативы — остальные по цене.
4. Считает сплит «компания vs сотрудник» и собирает payload для виджета.

Квиз-вариант (`bleisure-quiz/bleisure.js`) переиспользует ту же транспортную и
сплит-логику, но вместо списка отелей строит 4 коллекции «под вайб».

### 3. MCP-клиент

`callTool(name, args)` — минимальный JSON-RPC-клиент поверх HTTP:
`tools/call` → `result.content[0].text` → `JSON.parse`. Без внешних SDK.

### 4. Презентационный слой (serverless)

`api/*.js` парсят query-параметры, зовут `computeBleisure`, отдают JSON с
`Access-Control-Allow-Origin: *` и человекочитаемой ошибкой при сбое.

## Ключевые решения

- **Zero-dependency** — только стандартная библиотека Node 18+ (`fetch`, `http`,
  `fs`). Нет сборки, нет lock-файлов, минимум точек отказа; быстрый cold start
  на serverless.
- **Dumb frontend** — вся бизнес-логика на бэкенде; виджет переиспользуем в любом
  host-приложении (HR-портал, корпсайт, интранет).
- **Read-only + deeplink** — сервис не бронирует и не создаёт корзину на сервере;
  отдаёт пользователю готовые ссылки Tutu. Оплата всегда в браузере пользователя.
- **Payload-контракт** — схема ответа зафиксирована (см. `sample-data.json`), что
  позволяет развивать фронт и бэк независимо.

## Известные ограничения

- Даты выходных подбираются автоматически (суббота/воскресенье), ручной выбор —
  в планах.
- `search_*` вызываются последовательно; параллелизация и кэш — следующий шаг
  оптимизации (важно для стабильности на serverless).
- Курируемый блок «что посмотреть» убран: хардкод по городам плохо масштабируется.
